# 筋トレ記録アプリ 設計 v0.2

> ステータス: 設計中（「※要確認」が残件）

## 1. 目的
- スマホで、トレーニング中に最小タップで記録する
- 種目ごとに、前回より 1kg（kg×rep）でもボリュームが上がる次回メニューを自動提案する
- 休憩タイマーは作らない

## 2. 技術構成
| 層 | 採用 |
|---|---|
| フロント | Vite + React + TypeScript + Tailwind CSS（全画面クライアント描画。オフライン前提のため Next.js から変更） |
| 端末内DB | IndexedDB (Dexie) |
| ホスティング | Vercel |
| DB / 認証 | Supabase (Postgres + Auth)。利用者は自分のみ。メール+パスワードでログイン、新規登録は無効化、RLSで本人のみアクセス |
| 端末 | PWA（ホーム画面追加・フルスクリーン）、縦持ち片手操作 |

### Supabase の準備（Claude はこのセッションで接続しない）
- 実装時に `supabase/migrations/*.sql` と手順書 `docs/SETUP.md` を用意
- ユーザーが別アカウントで作成し、`URL` と `anon(publishable) key` を Vercel の環境変数に設定
- `service_role key` は共有不要

## 3. 重量とボリューム

### 重量の定義（画面に表示・記録する値）
| 器具タイプ | 記録する重量 | 既定の刻み |
|---|---|---|
| バーベル | バー20kg + プレート合計 | 2.5kg |
| EZバー | EZバー本体（既定10kg ※要確認・設定で変更可）+ プレート合計 | 2.5kg |
| ダンベル / マシン | 表示重量そのまま | 種目ごとに設定 |
| 自重 | 加重分のみ（補助はマイナス。例: アシスト懸垂 −10kg） | 2.5kg |

- 入力は合計重量を大きく表示し ±刻み で増減。バー系は小さく「片側 xx kg」を併記
- キーボード入力は使わない（ステッパーのみ）

### ボリューム
- **セットボリューム** = 有効重量 × 厳密レップ数
  - 通常種目: 有効重量 = 記録重量
  - 自重種目: 有効重量 = その日の体重 + 加重（補助はマイナス）
- **種目ボリューム** = その日の該当種目の全セット合計 ← **比較・提案の単位**
- **1日総ボリューム** = 全種目合計（参考表示）
- チーティング回数は**ボリュームに加算する**（有効重量 ×（厳密回数 + チーティング回数））。**達成判定には含めない**（重量を上げるかは厳密回数で決める）。前回の実績表示では `3+1` と書く

### 体重
- 設定に現在体重を保持。セッション開始時の値をセッションに保存（後から体重が変わっても過去のボリュームは不変）

## 4. 次回提案ロジック（種目ごと・ピラミッド法）

### セット構成
| 区分 | 内容 |
|---|---|
| メインセット | 最大重量 × 目標レップ × 5セット（目標レップは種目ごとに設定。例: 3） |
| バックオフセット | 最大重量の 60%（刻みに丸め）で限界まで。**回数は固定しない** |

- ピラミッド法は種目ごとに ON/OFF（既定 ON）
- 「全セット達成」の判定はメインセットのみ

### 入力
- 前回のメインセット実績（重量・厳密レップ）
- 前回の疲労度（0〜100 のゲージ値。下記で3区分に丸める）
- 前回の種目ボリューム（メイン + バックオフ）

| ゲージ | 区分 |
|---|---|
| 0〜33 | 軽 |
| 34〜66 | 普 |
| 67〜100 | 重 |

### メインセットの判定
1. **全セットで目標レップ達成** → 必ず重量を上げる。レップは目標値に戻す
   - 軽 → +刻み×3（例 +7.5kg）
   - 普 → +刻み×2（例 +5kg）
   - 重 → +刻み（例 +2.5kg）
2. **未達**（疲労度に関わらず）。重量は最大重量で据え置き、増やすのは「一番小さい1歩」だけ。低回数を崩さない（提案レップは目標を超えない）
   1. セット数が足りない → 足りないセットを目標レップで足す（済んだセットは増やさない）。例: 3,3,2,2（4セット）→ 3,3,2,2,3
   2. レップは全セット届いたが重量が揃っていない → 最大重量 × 目標レップ。例: 100×3,3,3 · 95×3,3 → 100×3,3,3,3,3
   3. レップが足りないセットがある → 一番少ないセットを +1。例: 3,3,3,2,2 → 3,3,3,3,2
3. 前回記録なし → 目標レップ × 5、重量は空欄（初回のみ手動で設定）

### バックオフセットの提案
- 重量 = 次回メイン重量 × 60%（刻みに丸め、バー重量未満にはしない）
- 回数は目標として固定せず、**前回の種目ボリュームを上回るのに必要な回数**を目安表示
  - `必要回数 = ceil((前回種目V − 今回メインV + 1) ÷ バックオフ重量)`（0以下なら表示なし）
  - 今回メインV は実績が入るたびに再計算（メインで想定より少なければ必要回数が増える）
- 重量アップでメインのボリュームが減ることは許容し、バックオフの回数で補う

例（目標 3×5、前回 100kg 3,3,3,3,3 / 60kg×10 = 種目V 2100、疲労 普）
```
次回メイン      105kg 3,3,3,3,3   = 1575
次回バックオフ  62.5kg (105×0.6=63→62.5) × ≥9  （1575 + 62.5×9 = 2137.5 > 2100）
```

### 自重種目のバックオフ
- 有効重量（体重+加重）の 60% を目標とし、加重値に換算（多くの場合マイナス＝補助）
- 例: 体重70kg・加重+10kg → 有効80kg×0.6 = 48kg → 加重 −22.5kg（補助）

## 5. データモデル
```
settings        user_id, body_weight_kg, ez_bar_kg(既定10), smith_bar_kg, measure_interval_days, height_cm(null可), sex(male|female 既定 male), weekly_sets(既定10)
exercises       id, user_id, name, equipment(barbell|ez|dumbbell|machine|bodyweight),
                weight_step, target_reps, main_sets(既定5), pyramid(既定true),
                backoff_ratio(既定0.6), sort_order, archived,
                movement(null可。下記「動き」), anchor(既定false。軸の種目。部位ごとに1つ)
routines        id, user_id, name, sort_order               -- 旧メニュー（例: 胸の日）。新しくは作らない。過去の回の名前にだけ使う
routine_items   routine_id, exercise_id, sort_order
sessions        id, user_id, routine_id(null可。部位から組んだ回は null), date, body_weight_kg
session_exercises
                id, session_id, exercise_id, fatigue(0-100, 既定50), comment
sets            id, session_exercise_id, set_no, kind(main|backoff),
                weight_kg, reps, cheat_reps
```
- ID はすべてクライアント生成の UUID（オフライン同期で重複しないように）
- 提案は保存せず、前回の実績から都度計算（純関数としてテストを書く）

### オフライン対応
- 記録操作は端末内（IndexedDB）に即保存 → 送信待ちキューに積む
- オンライン復帰時・アプリ起動時にキューを Supabase へ upsert（同じ UUID なので再送しても重複しない）
- マスタ（種目）と直近の実績は端末にキャッシュし、圏外でも提案を計算できる
- 未送信がある間は画面隅に小さなインジケータのみ表示

## 6. 画面
文言は最小。数値・アイコン中心。

### 数字とラベルの規約
画面をまたいで同じ役割の文字は同じ大きさにする。

| 階層 | 大きさ | 単位 | 使う場所 |
|---|---|---|---|
| 主役 | `text-[56px] leading-none tracking-tight` | 付けない | 記録画面の種目ボリューム / 今日の合計（TODAY）/ 履歴の累計（TOTAL）/ からだの見出しの数字。例外: からだの `胸囲 +2` は増減だけでは意味が通らないので、小さく（11px・dim）`cm` を添える |
| 脇役 | `text-[26px]` | 付けない | 記録画面のセット行（重量・レップ・バックオフ）。列の見出しで自明で、片側の重量は下に `片 xx` |
| 一覧の数値 | `text-lg`（ホームの帯のみ `text-base`） | 単位があれば `text-[10px] text-faint` で添える（`kg` / `cm`） | 設定の種目行、ホームのからだの帯（変化・あと）など。履歴の行のボリュームは単位なし |
| 注釈 | `text-[11px]` | — | ラベル、日付、ヒント、`片 xx`、左/右の印、曜日。数値に付く単位だけは 10px のまま |

- 英語の大文字ラベル（`text-[11px] tracking-[0.2em]` / `tracking-[0.15em]`）は見出しにだけ使う: NEXT / TOTAL / TODAY / SINCE … / BODY / EXERCISE / ADD / BACK-OFF / WEEK / GROWTH / MONTH。ボタンや本文中の語は日本語にする（セット n、今、体重、入力欄のヒント など）
- 薄い文字色 `--color-faint` は明るい場所でも読めるよう `#5a5a5a`（旧 `#4a4a4a`）
- 前回の実績行は日付を faint、セットを dim、`= 合計` を fg にして読む順番をつける

### ホーム
- 中央に全身の 3D ワイヤーフレーム（履歴と同じ Figure3D）。次に鍛える部位（今日始めていれば今日の部位）を白く明滅させる。モーションは記録画面の背景と同じランダム（8〜15 秒ごとに移り変わる）。スワイプで回転、タップでモーション切り替え。three.js の読み込み中は従来の線画を出す
- その下のボタン
  - 今日まだ始めていない: 「NEXT 胸・腕 →」。次に鍛える部位（`lib/plan.ts` `nextParts`）= ここ 28 日に鍛えた部位のうち、最後に鍛えてから一番空いているもの。同じ日に鍛えてそれ以来やっていない部位はまとめて出す。28 日以内になければ鍛えたことのある部位から、一度もなければ「今日を組む」。タップで今日を組む（部位を選んだ状態で）
  - 今日始めている: 「TODAY 胸・腕 →」と `記録した種目/全種目`。タップで記録画面へ
- 下に6部位の線画アイコン（横一列。スクロールしない）。最後に鍛えた日を小さく。タップでその部位を選んだ状態で今日を組む（今日始めていれば組み直し）
- 月の初めの7日間、前の月に記録があれば上に「10月のふりかえり　見る ×」（計測のお知らせと同じ形）。「見る」で履歴のその月のまとめへ（`/history?month=2026-10`）。見るか × でその月の分は出さない（localStorage `review-seen`）。計測のお知らせが出ている間はそちらを優先して出さない
- 部位の「最後に鍛えた日」と「前回の種目」は `repo.ts` `recentByPart`: 記録のある種目があった一番新しい回

### ホームの動き
- 背景（src/ui/Backdrop.tsx）: 白の粒子（35 個、ごく薄く）がゆっくり昇り、さざ波の輪は全身図の外側（短辺の 28%）から 7 秒周期で広がって消える（3本ずらし）。動くのは中央とその足元だけ、周辺は息をしている程度
- 全身図（src/ui/Figure3D.tsx）: 触ってから 20 秒は自転しない（スワイプ後の惰性は残る）。そのあとゆっくり自転に戻る
- 開いたとき、全身図 → NEXT → 数字の帯 → 連なり → 部位 の順に 0.15 秒ずつ浮かび上がる（`.rise`）
- 全身図の足元に輪。4.5 秒周期で呼吸する（`.breathe`）
- NEXT の矢印が 3.2 秒ごとに右へ少し動いてうながす（`.nudge`）
- 連なりの最新のドットから輪が脈打って広がる（`.pulse-ring`）
- 減速モーション設定ではすべて止める

### 線画（src/ui/BodyArt.tsx）
- 種目に部位（胸/背中/肩/腕/脚/腹）を設定する。ホームの部位アイコンはその部位の模様、3D の読み込み中の線画は次に鍛える部位の模様を重ねる
  - 胸: 胸骨から肩へ集まる扇 / 背中: 腰へ絞れる V 字 / 肩: 重なるドーム / 腕: 紡錘形の波 / 脚: 2本の柱 / 腹: 2×3 の区画
- 激しさ = 次回提案の挑戦度の平均（progression.ts `challenge`）
  - 軽で全達成(+3刻み) 1.0 / 普 0.75 / 重 0.55 / 未達の再挑戦 0.35 / 初回 0.2
  - 高いほど線が増え、速く大きく揺れ、細かく震える

### 記録画面（メイン）
```
ベンチプレス          1530  ▲30
片側 40
┌─────────────────────────────┐
│ 100 ×3  ⓒ0        [✓]       │ ← 提案値が入った状態
│ 100 ×3  ⓒ0        [✓]       │
│ 100 ×3  ⓒ0        [  ]      │
│  …                            │
├─────────────────────────────┤
│  60 × ≥10  ⓒ0     [  ]      │ ← バックオフ（必要回数を目安表示）
└─────────────────────────────┘
 [＋]
 軽 ━━━━━━●━━━━━━ 重
 💬
```
- 提案どおりなら **✓ 1タップ = 1セット記録**（即保存）
- 次に押す ✓（最初の未記録セット）だけが白、ほかの未記録は灰。記録した瞬間、その ✓ から細い白の波紋が広がり（500ms）、端末が 10ms だけ震える（動きを減らす設定では波紋なし）
- 3D の線で数字が読みにくくならないよう、ボリューム周りは放射状、セット一覧は横一面の帯で、背面に半透明の黒をにじませる（カードにはしない。位置は変えない）
- 数値タップ → その場で ± ステッパー（重量 ±刻み / レップ ±1 / チート ±1）
- 数字は長押し（350ms）してそのままドラッグで調整（重量は左右 24px = 1刻み、回数・チートは上下 20px = 1）。動かしている間は数字に `bg-chip`。長押し前に動かすとふつうのスクロール / スワイプ
- 記録取消は下の小さな通知「取り消しました　戻す」で戻せる（2.5秒）
- メインセットが全部そろう（またはバックオフを記録する）と、0.3秒後に疲労ゲージへ自動スクロール（減速モーション設定ではジャンプ）
- 疲労ゲージは既定で中央。スライドで調整（細かい目盛り、0〜100）。横長の長方形のゲージ（src/ui/FatigueGauge.tsx。高さ 64px、細い枠線）: つまみは長方形の高さいっぱいの縦線。左端からつまみまでのあいだに幾何学の曲線の束を描く。軽いほど本数が少なくゆるやかにゆっくり流れ、重いほど本数・振幅・周波数・速さが増し細かく震える。束は左端とつまみで1点に集まる
- 💬 タップでコメント欄を展開
- 種目間は左右スワイプで移動、上部にドットで位置表示
- 上部に今日の種目ボリュームと前回比をリアルタイム表示
  - 前回を超えるまでは「あと N」（前回 +1 までの残り）、超えたら白で「+N」
  - 前回の実績行には種目ボリュームも併記（`10/03　100×3,3,3,3,3 · 60×10 = 2,100`）
- 終了ボタンなし（全操作が即時保存）
- 背景に全身の 3D（Figure3D。薄く 25%、高さ 62%）。開いている種目の部位を白く明滅させる。モーションは部位に決まったものがなければランダム（入っているものから無作為に選び、8〜15 秒ごとに別のものへ）。操作は受けない（スワイプは種目送りのまま）
- 今日の予定はその場で変えられる
  - 下のドットの右端（片手で届く右下）に一覧のボタン → 組み直す（今日を組むと同じ画面で、種目の一覧から始まる）。順番・足す・外す・部位を変えるをまとめて
  - 各パネルの一番下に「◀ 順番 ▶」「種目を変える」「今日はやらない」
  - 順番: 隣のパネルと sort_order を交換し、そのパネルへスクロール
  - 種目を変える: 記録がないパネルだけ。下からの一覧「◯◯ の代わり」で今日にない種目を選ぶと、順番はそのままで差し替わる。並びは 同じ動き → 同じ部位のほかの種目（どちらもまだ作っていない事前登録を含み、選んだ時点で作る）→ ほかの部位の作成済みの種目（今日の部位を先に、部位ごと）。右に今の最大重量（記録がなければ器具）
  - 今日はやらない: 記録があれば確認してから、記録ごと外す（deleted）
  - 最後のパネルの ADD も部位ごと（今日の部位を先に）

### 前進感の仕掛け（色・絵文字は使わず、数字と白の濃淡だけで）
| 場面 | 仕掛け |
|---|---|
| 前回を超えた瞬間 | ボリュームの数字がひと呼吸ふくらみ（`animate-beat`）、端末が短く震える（`navigator.vibrate(40)`）。「あと N」が白い「+N」に変わる |
| 記録中 | 「あと N」の横に、提案どおりの次のセットで超えるなら「次のセットで超える」。進み具合の線は前回の位置に目盛りがあり、超えた分は目盛りの先へ伸びる（最大 +15%）。種目ドットは前回を超えた種目が白く灯る。メインセットを全部記録すると疲労ゲージの下に「次回 105 kg（+5）」が出て、ゲージを動かすとその場で変わる |
| 種目ごと | 数字の下に「N回連続更新中」（まだ超えていない: 守るもの）/「N回連続で更新」（超えた: 伸びたもの）。メイン最大重量が過去最高なら「自己ベスト 105」 |
| セッションの終わり | 最後のパネル（種目追加の上）に「今日のまとめ」: 合計ボリューム / 前回比 / 更新 N/M 種目 / 自己ベスト数。終了ボタンの代わりの到達点 |
| 履歴 | 上部に全身の幾何学図。目標のプロポーション（下記）に足りない部位を斜線で強調し、「NEXT: 前腕 あと 3 cm　腕」と鍛える部位を提案する。その下に全期間の累計ボリューム・回数・更新 N/M 種目。減ることのない数字 |
| からだ | 上部に初回からいちばん伸びた部位を大きく（`胸囲 +2`）、下に「大きくなった N/M 項目 · 今が最大 N」。体重とウエストは増減どちらが良いか人によるので数えない（`GROWTH_KEYS`）。一覧の「今」は今が過去いちばん（ウエストは最小）なら白、そうでなければ灰。最後の計測からのトレーニング回数と更新種目数も一行で出し、次の計測への期待にする |
| 計測入力 | 上に「前回より大きく 3 · 今が最大 2」を入力しながら更新。各項目にプロポーション目標（`目標 109.5`）を小さく。過去いちばんになった値には「最大」 |
| 初回チュートリアル | 1枚目で体重と身長を聞く（身長はプロポーション目標の基準）。使い方に「前に進んだことが見える」の1枚を追加（5枚） |
| ログイン | 波の下に、この端末に残っている積み上げ「12回 · 累計 13,486」。何もなければ「前回を、1kgでも超える。」 |
| 今日を組む | ① 部位: 問いの下に「目標のプロポーションに足りないのは 腕・胸」、該当する部位カードの右上に白い点（履歴の NEXT 上位3項目から。全部に印がつかないよう上位だけ）。各カードに最後に鍛えた日。② 種目: 今日の種目は名前の下に今の最大重量と「次は重量アップ」、足せる種目は右に今の最大重量と「+10 · 次は重量アップ」。自己ベスト一覧から選ぶ感覚に |
| 設定 | 見出しの下に「09/26 から 42日 ・ 12回」。種目一覧の各行の右に今の最大重量を大きく、初回からの伸び（`+10`）を白で小さく。自己ベスト一覧として読める |
| ホーム（からだの数字） | 常に2行出す。上段: 初回からの計測の変化を大きい順に横並び（`胸囲 +2  肩周り +2  ウエスト −0.5`。左右は平均、0 は出さない）。下段: 魅力的な体まで「あと」何cmかを不足の割合が大きい順に3つ（`胸囲 9.5cm  前腕 3cm  上腕 2.5cm`）。左端の日付と「あと」は固定し、その右だけが一定の速さ（28px/秒）で右から左へ流れてループ（入り切るときは動かさない。減速モーション設定では止める）。計測がなければ計測へ、身長がなければ設定へ誘導。タップで「からだ」へ |
| ホーム | NEXT の下に今日の見どころ「重量アップ N 種目」（次に鍛える部位の前回の種目のうち、前回全セット達成で重量が上がる種目数）。始めていれば TODAY の下に `1/4 種目`。その下に直近 12 回の連なり: 全種目で前回超え = 白丸、一部 = 灰の輪、なし = 薄い輪。タップで履歴へ |

- 連続更新は `progression.ts` の `streak`（新しい順の種目ボリューム列で「前より大きい」が続く数）
- 過去の実績一覧は `repo.ts` の `exerciseHistory`（記録なしの回は除く）

### プロポーション目標（src/lib/ideal.ts）
身長と直近の計測から、各部位の推奨目標を出す。独自ロジックで、根拠にした指標は次のとおり。

| 比率 | 値 | 根拠 |
|---|---|---|
| ウエスト / 身長 | 0.45 | WHtR。健康・見た目の両面で良いとされる 0.40〜0.50 の中央 |
| 肩周り / ウエスト | 1.618 | 黄金比（Adonis index）。男性が最も魅力的に映るとされる肩と腰の比 |
| ウエスト / 臀囲 | 0.90 | 男性で最も魅力的と評価された WHR（Singh の研究） |
| 胸囲 | ウエスト ÷ 0.70 | McCallum の古典的理想比率 |
| 上腕（力こぶ）/ 前腕 / 大腿 / ふくらはぎ | 胸囲 × 0.36 / 0.29 / 0.53 / 0.34 | 同上（上腕 ≒ ふくらはぎ。Reeves の対称律と整合） |

- 基準ウエスト = min(今のウエスト, 身長 × 0.45)。理想より太ければ理想値を基準に（細くする目標が立つ）、すでに細ければ今の値を基準に（細い人に太るよう勧めない）
- 目標は 0.5cm 刻みに丸める。不足 0.5cm 未満は達成扱い
- 「次に伸ばす」は不足の割合（不足 ÷ 目標）が大きい順。左右がある項目は弱い方で判定。各項目には鍛える部位（肩周り → 肩・背中、臀囲 → 脚 など）を添える
- 身長は設定（BODY）に持つ。未設定なら目標は出さず、全身図は標準体（身長 170 の目標比）を灰で描くだけ
- からだ画面の推移（行をタップ）にも「目標 X · あと Y」を出す

### 履歴

  - 計測値は骨の X/Z スケール（太さ）に写す。目標に対する今の比を 1.5 倍に誇張し 0.85〜1.2 に収める。子の骨は親の分を打ち消す。近似であり cm に忠実ではない
  - 足りない部位は、頂点の主な骨がその部位の骨なら白く明滅、ほかは灰（三角形を2グループに分け材質を2つにする）

  - 体型は設定の「体型」（男性 / 女性）。男性は骨のスケールのプリセットで肩を広く厚く、胸・首・腕・脚を太く、腰を細くする（X Bot 自体は中性的）。計測の比はその上に掛ける
  - 減速モーション設定では立ち姿（idle）で止める
  - Mixamo のキャラクターはアプリ内での利用は無償で可。単体での再配布はしない

  - 「10月のまとめ」（今月は「（11/10まで）」と添える）の下に `5回 · 合計 11,127 · 更新 4/5 種目`
  - 部位ごとの表（その月に鍛えた部位、または軸の種目の記録がある部位）: 重量 = 軸の種目の推定1RMの変化（前の月の最後の回 → その月の最後の回。前の月になければその月の最初の回から。`lib/growth.ts` `changeIn`）、見た目 = 同じ部位の計測の変化（同じ決め方）、週のセット = その月のセット数の1週間あたり / 目安（今月は今日までの日数で割る。`perWeek`）。増えた変化と目安に届いた週のセットは白、比べられなければ「—」

  - 「記録を見る」で一覧（新しい順に 日付 · 一番高かったセット · 推定1RM）。グラフを読めなくても値に届く
  - 軸の種目がなければ、決め方の案内だけ出す

### 今日を組む（/today）
保存したメニューは持たない。対象部位はその日に決め、混雑や体調・痛みで種目や部位を変える前提。
- 入口: ホームの NEXT（次に鍛える部位を選んだ状態）/ ホームの部位アイコン（その部位を選んだ状態）/ 記録画面右下の一覧ボタン（`?s=セッションID`。組み直し）
- 今日のセッションがなければ ① 部位 → ② 種目 → 開始。あれば組み直し（② 種目から始まる。戻ると記録画面へ）
- ① 部位（複数可）。各カードに「今週 4/10」（直近7日のセット数 / 目安。目安に届いていれば白）と最後に鍛えた日
- ② 種目
  - 一番上に WEEK: 選んだ部位（と今日の種目の部位）ごとに、今週のセット数の線。直近7日に記録した分を白、この組み方で足す分を灰で続けて伸ばし、目安の位置に目盛り（線は目安の1.5倍まで）。右に `合計 / 目安`（届いていれば白）。種目を足す・外すとその場で変わる
    - 記録した分 = 直近7日（今日を含む）の記録したセット（メイン + バックオフ）を種目の部位ごとに（`repo.ts` `weekSetsByPart`）。組み直し中のセッションは記録ではなく予定で数える
    - 予定 = 種目ごとに メインセット数 + バックオフ1（ピラミッドなら）（`lib/plan.ts` `plannedSets`）。まだ作っていない事前登録は初期設定のセット数
    - 週1〜2回だと1回でまとめて稼ぐので、組みながら足りているかを見るため
  - その下に TODAY: 今日やる種目をこの順で。上下で並べ替え、× で外す。今日記録した種目は「記録あり」と出し、外すときは確認して記録ごと外す
  - 部位を選ぶと、その部位の軸の種目を先頭に、その部位を前回やった回の種目（`recentByPart`）が続けて最初から入っている（`lib/plan.ts` `seedExercises`）。部位を外すとその部位の種目も外れる（記録した種目は残す）
  - 軸の種目は名前の右に小さな「軸」
  - 名前をタップするとその下が開く: 「◯の軸の種目」のスイッチ（作成済みの種目だけ）と、代わりの種目（同じ動き。動きがなければ同じ部位。今日に入っていないもの）。代わりをタップすると同じ位置で入れ替わる。今日記録した種目は入れ替えない
  - 下に選んだ部位ごとの、今日に入っていない種目。部位の中は動きごとに小見出し（押す / 斜め上に押す / 開く …、動きのない種目は「その他」）。タップで TODAY の最後に足す
  - 「部位を変える」で ① へ、「一覧にない種目」で新規作成（名前・部位・動き（任意）・器具・高重量/中重量を選ぶ）
- 開始 / 決定を押すまで何も保存しない。押すと今日のセッションを作る（routine_id は null）か、組み直すセッションの種目を並び順どおりに置き換える（残る種目は記録ごとそのまま、外した種目は記録ごと deleted）
- 事前登録の種目（src/lib/presets.ts）は開始した時点で種目として作られる
- 前回の実績と次回提案は種目ごとに探すので（`previousPerformance`）、どの組み方をしても前回から続く

### からだ（/body, /body/measure）
- メジャー計測: 体重・ウエスト・胸囲・肩周り・上腕（脱力/力こぶ 左右）・前腕・大腿・ふくらはぎ（左右）・臀囲
- 一覧: 最新値と、前回・初回からの変化。行をタップでその項目の推移（細い折れ線 + 計測ごとの値と前回差。src/ui/Sparkline.tsx）
- 入力: 前回の値から始め、変わった項目だけタップで増減（cm は 0.5、体重は 1kg 刻み）。同じ日は上書き。体重は設定にも反映
- お知らせ: 最終計測日 + 間隔（設定で 1/2/4 週、既定 2 週）を過ぎるとホームに「そろそろ計測の時期です」。× で当日は非表示

### 設定
- 体重 / 身長（プロポーション目標の基準。未設定は「—」）/ 体型（男性 / 女性。全身図の骨格プリセット）/ EZバー / スミスバー（タップで増減。体重は1kg単位）/ 計測の間隔 / 週のセット数の目安（部位ごと。6・8・10・12・15・20 から。既定 10。筋肥大でよく使われる「週10セット前後から」に合わせた）
- 種目の細かい設定（部位・動き・軸の種目・器具・刻み・回数・セット・ピラミッド・バックオフ）。軸の種目は一覧の行の頭に「軸」。部位を変えると軸は外れる

### 軸の種目と動き
目標は見た目（筋肥大）。写真の代わりにメジャー計測で結果を見て、毎回の数字の目標は重量に置く。ただし混雑で種目や器具をよく替えるので、伸びを測る種目と、替えてよい種目を分ける。
- 軸の種目: 部位ごとに1つ、その部位の伸びを測る種目（例: 胸 = ベンチプレス）。設定か、今日を組むの種目を開いたところで決める。ほかの軸は自動で外れる（`repo.ts` `setAnchor`）。今日を組むとき部位の先頭に入り、記録画面の見出しの下に「軸 ·」
- 動き（`types.ts` `MOVEMENTS`）: 同じ動きなら器具や種目を替えても同じところに効く、というまとまり。胸 = 押す / 斜め上に押す / 開く、背中 = 上から引く / 手前に引く / 起こす、肩 = 頭上に押す / 横に上げる / 前に上げる / 後ろに引く / すくめる、腕 = 曲げる / 伸ばす、脚 = しゃがむ / お尻・もも裏 / ひざを伸ばす / ひざを曲げる / ふくらはぎ、腹 = 丸める / 脚を上げる
- 事前登録の種目はすべて動きを持つ（presets.ts）。種目の movement が null なら同名の事前登録から引く（`movementOf`。事前登録から作った種目は名前が同じなので、既存の種目もそのまま動きがつく）。部位と合わない動きは無しとみなす
- 混雑時の代わりは、今日を組む（種目を開く）と記録画面の「種目を変える」で、同じ動きの種目を先に出す
- 数値はすべて ±ボタンか候補から選ぶ。キーボードは名前・コメント・ログインのみ

## 7. 確定事項メモ
- バックオフセットは1セット
- 刻みへの丸めは最も近い倍数（同距離なら軽い方）
