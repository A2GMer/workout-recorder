# 筋トレ記録アプリ 設計 v0.2

> ステータス: 設計中（「※要確認」が残件）

## 1. 目的
- スマホで、トレーニング中に最小タップで記録する
- 種目ごとに、前回より 1kg（kg×rep）でもボリュームが上がる次回メニューを自動提案する
- 休憩タイマーは作らない

## 2. 技術構成
| 層 | 採用 |
|---|---|
| フロント | Vite + React + TypeScript + Tailwind CSS（全画面クライアント描画。オフライン前提のため Next.js から変更） |
| 端末内DB | IndexedDB (Dexie) |
| ホスティング | Vercel |
| DB / 認証 | Supabase (Postgres + Auth)。利用者は自分のみ。メール+パスワードでログイン、新規登録は無効化、RLSで本人のみアクセス |
| 端末 | PWA（ホーム画面追加・フルスクリーン）、縦持ち片手操作 |

### Supabase の準備（Claude はこのセッションで接続しない）
- 実装時に `supabase/migrations/*.sql` と手順書 `docs/SETUP.md` を用意
- ユーザーが別アカウントで作成し、`URL` と `anon(publishable) key` を Vercel の環境変数に設定
- `service_role key` は共有不要

## 3. 重量とボリューム

### 重量の定義（画面に表示・記録する値）
| 器具タイプ | 記録する重量 | 既定の刻み |
|---|---|---|
| バーベル | バー20kg + プレート合計 | 2.5kg |
| EZバー | EZバー本体（既定10kg ※要確認・設定で変更可）+ プレート合計 | 2.5kg |
| ダンベル / マシン | 表示重量そのまま | 種目ごとに設定 |
| 自重 | 加重分のみ（補助はマイナス。例: アシスト懸垂 −10kg） | 2.5kg |

- 入力は合計重量を大きく表示し ±刻み で増減。バー系は小さく「片側 xx kg」を併記
- キーボード入力は使わない（ステッパーのみ）

### ボリューム
- **セットボリューム** = 有効重量 × 厳密レップ数
  - 通常種目: 有効重量 = 記録重量
  - 自重種目: 有効重量 = その日の体重 + 加重（補助はマイナス）
- **種目ボリューム** = その日の該当種目の全セット合計 ← **比較・提案の単位**
- **1日総ボリューム** = 全種目合計（参考表示）
- チーティング回数はボリュームにも達成判定にも**含めない**（別欄で記録・表示のみ）

### 体重
- 設定に現在体重を保持。セッション開始時の値をセッションに保存（後から体重が変わっても過去のボリュームは不変）

## 4. 次回提案ロジック（種目ごと・ピラミッド法）

### セット構成
| 区分 | 内容 |
|---|---|
| メインセット | 最大重量 × 目標レップ × 5セット（目標レップは種目ごとに設定。例: 3） |
| バックオフセット | 最大重量の 60%（刻みに丸め）で限界まで。**回数は固定しない** |

- ピラミッド法は種目ごとに ON/OFF（既定 ON）
- 「全セット達成」の判定はメインセットのみ

### 入力
- 前回のメインセット実績（重量・厳密レップ）
- 前回の疲労度（0〜100 のゲージ値。下記で3区分に丸める）
- 前回の種目ボリューム（メイン + バックオフ）

| ゲージ | 区分 |
|---|---|
| 0〜33 | 軽 |
| 34〜66 | 普 |
| 67〜100 | 重 |

### メインセットの判定
1. **全セットで目標レップ達成** → 必ず重量を上げる。レップは目標値に戻す
   - 軽 → +刻み×3（例 +7.5kg）
   - 普 → +刻み×2（例 +5kg）
   - 重 → +刻み（例 +2.5kg）
2. **未達**（疲労度に関わらず）。重量は最大重量で据え置き、増やすのは「一番小さい1歩」だけ。低回数を崩さない（提案レップは目標を超えない）
   1. セット数が足りない → 足りないセットを目標レップで足す（済んだセットは増やさない）。例: 3,3,2,2（4セット）→ 3,3,2,2,3
   2. レップは全セット届いたが重量が揃っていない → 最大重量 × 目標レップ。例: 100×3,3,3 · 95×3,3 → 100×3,3,3,3,3
   3. レップが足りないセットがある → 一番少ないセットを +1。例: 3,3,3,2,2 → 3,3,3,3,2
3. 前回記録なし → 目標レップ × 5、重量は空欄（初回のみ手動で設定）

### バックオフセットの提案
- 重量 = 次回メイン重量 × 60%（刻みに丸め、バー重量未満にはしない）
- 回数は目標として固定せず、**前回の種目ボリュームを上回るのに必要な回数**を目安表示
  - `必要回数 = ceil((前回種目V − 今回メインV + 1) ÷ バックオフ重量)`（0以下なら表示なし）
  - 今回メインV は実績が入るたびに再計算（メインで想定より少なければ必要回数が増える）
- 重量アップでメインのボリュームが減ることは許容し、バックオフの回数で補う

例（目標 3×5、前回 100kg 3,3,3,3,3 / 60kg×10 = 種目V 2100、疲労 普）
```
次回メイン      105kg 3,3,3,3,3   = 1575
次回バックオフ  62.5kg (105×0.6=63→62.5) × ≥9  （1575 + 62.5×9 = 2137.5 > 2100）
```

### 自重種目のバックオフ
- 有効重量（体重+加重）の 60% を目標とし、加重値に換算（多くの場合マイナス＝補助）
- 例: 体重70kg・加重+10kg → 有効80kg×0.6 = 48kg → 加重 −22.5kg（補助）

## 5. データモデル
```
settings        user_id, body_weight_kg, ez_bar_kg(既定10)
exercises       id, user_id, name, equipment(barbell|ez|dumbbell|machine|bodyweight),
                weight_step, target_reps, main_sets(既定5), pyramid(既定true),
                backoff_ratio(既定0.6), sort_order, archived
routines        id, user_id, name, sort_order               -- 例: 胸の日
routine_items   routine_id, exercise_id, sort_order
sessions        id, user_id, routine_id, date, body_weight_kg
session_exercises
                id, session_id, exercise_id, fatigue(0-100, 既定50), comment
sets            id, session_exercise_id, set_no, kind(main|backoff),
                weight_kg, reps, cheat_reps
```
- ID はすべてクライアント生成の UUID（オフライン同期で重複しないように）
- 提案は保存せず、前回の実績から都度計算（純関数としてテストを書く）

### オフライン対応
- 記録操作は端末内（IndexedDB）に即保存 → 送信待ちキューに積む
- オンライン復帰時・アプリ起動時にキューを Supabase へ upsert（同じ UUID なので再送しても重複しない）
- マスタ（種目・ルーティン）と直近の実績は端末にキャッシュし、圏外でも提案を計算できる
- 未送信がある間は画面隅に小さなインジケータのみ表示

## 6. 画面
文言は最小。数値・アイコン中心。

### ホーム
- 中央に「次にやるメニュー」（未実施 or 最後に行ってから一番空いているもの）の線画。タップで開始
- 下にメニューの円形アイコン。前回日付を小さく
- タップ → 当日のセッション開始（同日に既存があれば再開）

### 線画（src/ui/BodyArt.tsx）
- 種目に部位（胸/背中/肩/腕/脚/腹）を設定し、メニューは多い順に2部位の模様を重ねる
  - 胸: 胸骨から肩へ集まる扇 / 背中: 腰へ絞れる V 字 / 肩: 重なるドーム / 腕: 紡錘形の波 / 脚: 2本の柱 / 腹: 2×3 の区画
- 激しさ = 次回提案の挑戦度の平均（progression.ts `challenge`）
  - 軽で全達成(+3刻み) 1.0 / 普 0.75 / 重 0.55 / 未達の再挑戦 0.35 / 初回 0.2
  - 高いほど線が増え、速く大きく揺れ、細かく震える

### 記録画面（メイン）
```
ベンチプレス          1530  ▲30
片側 40
┌─────────────────────────────┐
│ 100 ×3  ⓒ0        [✓]       │ ← 提案値が入った状態
│ 100 ×3  ⓒ0        [✓]       │
│ 100 ×3  ⓒ0        [  ]      │
│  …                            │
├─────────────────────────────┤
│  60 × ≥10  ⓒ0     [  ]      │ ← バックオフ（必要回数を目安表示）
└─────────────────────────────┘
 [＋]
 軽 ━━━━━━●━━━━━━ 重
 💬
```
- 提案どおりなら **✓ 1タップ = 1セット記録**（即保存）
- 数値タップ → その場で ± ステッパー（重量 ±刻み / レップ ±1 / チート ±1）
- 疲労ゲージは既定で中央。スライドで調整（細かい目盛り、0〜100）
- 💬 タップでコメント欄を展開
- 種目間は左右スワイプで移動、上部にドットで位置表示
- 上部に今日の種目ボリュームと前回比をリアルタイム表示
  - 前回を超えるまでは「あと N」（前回 +1 までの残り）、超えたら白で「+N」
  - 前回の実績行には種目ボリュームも併記（`10/03　100×3,3,3,3,3 · 60×10 = 2,100`）
- 終了ボタンなし（全操作が即時保存）

### 前進感の仕掛け（色・絵文字は使わず、数字と白の濃淡だけで）
| 場面 | 仕掛け |
|---|---|
| 前回を超えた瞬間 | ボリュームの数字がひと呼吸ふくらみ（`animate-beat`）、端末が短く震える（`navigator.vibrate(40)`）。「あと N」が白い「+N」に変わる |
| 種目ごと | 数字の下に「N回連続更新中」（まだ超えていない: 守るもの）/「N回連続で更新」（超えた: 伸びたもの）。メイン最大重量が過去最高なら「自己ベスト 105」 |
| セッションの終わり | 最後のパネル（種目追加の上）に「今日のまとめ」: 合計ボリューム / 前回比 / 更新 N/M 種目 / 自己ベスト数。終了ボタンの代わりの到達点 |
| 履歴 | 上部に全期間の累計ボリューム・回数・更新 N/M 種目。減ることのない数字 |
| からだ | 上部に初回からいちばん伸びた部位を大きく（`胸囲 +2`）、下に「大きくなった N/M 項目 · 今が最大 N」。体重とウエストは増減どちらが良いか人によるので数えない（`GROWTH_KEYS`）。一覧の NOW は今が過去いちばん（ウエストは最小）なら白、そうでなければ灰。最後の計測からのトレーニング回数と更新種目数も一行で出し、次の計測への期待にする |
| ホーム | NEXT の下に今日の見どころ「重量アップ N 種目 · N回連続更新中」（前回全セット達成で重量が上がる種目数と、そのメニューで全種目更新が続いた回数）。その下に直近 12 回の連なり: 全種目で前回超え = 白丸、一部 = 灰の輪、なし = 薄い輪。タップで履歴へ |

- 連続更新は `progression.ts` の `streak`（新しい順の種目ボリューム列で「前より大きい」が続く数）
- 過去の実績一覧は `repo.ts` の `exerciseHistory`（記録なしの回は除く）

### 履歴
- 上部に累計（上記）
- 日付ごとの一覧 → タップで詳細（種目ボリューム・コメント・チート回数）
- 各行の右に「前回を超えた種目数 / 前回と比べられた種目数」（例: `2/3`。全部超えたら白）
- グラフは後回し

### 初回チュートリアル（/welcome）
- メニューが1つもなく未完了なら自動で表示。一方通行
- はじめに → 体重 → メニュー作成（部位 → 種目 → 順番と名前） → 使い方（4枚）
- 設定の「使い方を見る」で使い方だけ再表示（/welcome?howto）

### メニュー作成（/menu/new, /menu/:id）
- 入口: ホーム下段の「＋ メニュー作成」/ 設定のメニュー一覧
- ① 部位（複数可） → ② 種目（選んだ部位の種目だけ。タップ順に並ぶ） → ③ 順番と名前（名前は部位から自動） → 完了
- 種目の新規作成は ② の「一覧にない種目」だけ（名前・器具・高重量/中重量を選ぶ）
- 事前登録の種目（src/lib/presets.ts）は選ばれた時点で種目として作られる
- 完了を押すまで何も保存しない

### からだ（/body, /body/measure）
- メジャー計測: 体重・ウエスト・胸囲・肩周り・上腕（脱力/力こぶ 左右）・前腕・大腿・ふくらはぎ（左右）・臀囲
- 一覧: 最新値と、前回・初回からの変化。行をタップでその項目の推移（細い折れ線 + 計測ごとの値と前回差。src/ui/Sparkline.tsx）
- 入力: 前回の値から始め、変わった項目だけタップで増減（cm は 0.5、体重は 1kg 刻み）。同じ日は上書き。体重は設定にも反映
- お知らせ: 最終計測日 + 間隔（設定で 1/2/4 週、既定 2 週）を過ぎるとホームに「そろそろ計測の時期です」。× で当日は非表示

### 設定
- 体重 / EZバー / スミスバー（タップで増減。体重は1kg単位）/ 計測の間隔
- メニュー一覧（タップでメニュー編集へ）
- 種目の細かい設定（部位・器具・刻み・回数・セット・ピラミッド・バックオフ）
- 数値はすべて ±ボタンか候補から選ぶ。キーボードは名前・コメント・ログインのみ

## 7. 確定事項メモ
- バックオフセットは1セット
- 刻みへの丸めは最も近い倍数（同距離なら軽い方）
